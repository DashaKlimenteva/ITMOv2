# Отчёт 2. Повторные атаки после исправлений

Проверка тех же сценариев на исправлённом сервисе.

1. /profile теперь требует сессию и возвращает только собственный профиль.
- GET /profile?id=2 с токеном alice -> 200, массив из одного профиля TEST_ALICE.

2. /search теперь параметризован и доступен только staff.
- GET /search?q=%' OR 1=1 -- с токеном alice -> 403.
- GET с токеном staff -> 200 и фильтр по LIKE.

3. /orders GET ограничен: клиент видит только свои, staff — все.

4. /admin/export авторизация из сессии, заголовок X-Role игнорируется.
- Без токена -> 401; alice -> 403; staff -> 200.

5. /files ограничен директориями пользователя.
- alice читает только files/alice/*; попытка files/bob/… -> 403.

6. Цена заказа фиксируется сервером по каталогу.
- Попытка указать price -> игнорируется, возвращается цена каталога.

7. /reviews/view экранирует HTML, XSS не исполняется.

8. Assistant
- context возвращает только заказы владельца; чужие id -> 404.
- execute: read_file только в своей директории; export/delete только staff.

Остаточные риски: DoS по диску/CPU за пределами объёма работы; staff может удалить фикстуры в пределах стенда.
