## Сравнение Spec Kit и OpenSpec
| Аспект | OpenSpec | Spec Kit |
|---|---|---|
| Структура | changes/ + archive/ | specify → plan → tasks → implement |
| Команды | $openspec-* | /speckit.* |
| Полнота спеки | человек на ревью | контракт UI↔Logic выявляет расхождения |
| Когда ловятся ошибки | после propose | до кода, на этапе contract |

## Чему научились
- Разделение UI и логики заставляет формально фиксировать контракт.
- Контракт выявил расхождение «код 1 vs 2 для --lab < 1», которое в OpenSpec-подходе осталось незамеченным.
- Нельзя доверять отчёту агента: tasks.md и design.md были пустыми, хотя агент писал «готово». Нужно проверять файлы напрямую.
- OpenSpec удобен для изменения в существующем проекте, Spec Kit — для контракта до кода.
