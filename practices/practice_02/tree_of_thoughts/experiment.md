- Решение, для которого нужны альтернативы: улучшение `practices/practice_01/tests_load.md` с учётом источников — `CASE.md (API-1, REL-1, QA-1, OBS-1)`, `problem.md → Метрики`, `TRAINING_PR.diff → app/api.py:35-38; app/review_service.py:19-22`.
- Критерии выбора: подтверждённость источником (QA-1), наличие числовых порогов, наличие критериев провала, связь с метриками `problem.md`, воспроизводимость (evidence и шаги).

## Запрос

Сформировать улучшенную версию нагрузочных тестов на основе подтверждённых правил `CASE.md` и строк `TRAINING_PR.diff`, учитывая метрику качества из `problem.md → Метрики`. Рассмотреть минимум три альтернативных подхода, выбрать лучший по критериям и создать `practices/practice_02/tree_of_thoughts/tests_load_improved.md`. Не менять `practices/practice_01/tests_load.md`.
## Внешне описанные альтернативы

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A. Минимально необходимая фиксация (только подтверждённые L1 и L3) | Максимальная подтверждённость (QA-1); чёткие пороги (20000, 10с); простая воспроизводимость; низкий риск нарушить OBS-1 | Не покрывает параллельность/пропускную способность | + по всем критериям, кроме охвата — нейтрально |
| B. Добавить экспериментальный L2 с мягкими допусками | Шире покрытие сценариев | Нет правил и метрик для порогов → нарушает QA-1; риск выдуманных чисел; ухудшает воспроизводимость | − по подтверждённости; − по воспроизводимости; − по критериям провала |
| C. Сфокусироваться на логировании и observability | Подчёркивает важность OBS-1; улучшает проверяемость журналирования | Не добавляет новых числовых порогов; не заменяет L2; может отвлечь от целей API-1/REL-1 | + по подтверждённости; ± по воспроизводимости; − по наличию порогов |

## Выбор

- Выбранная альтернатива: A. Минимально необходимая фиксация (только подтверждённые L1 и L3).
- Почему: удовлетворяет QA-1 (все сценарии подтверждены правилами/диффом), содержит числовые пороги (20000; 10с), имеет критерии провала, напрямую связана с метрикой «доля 5xx < 1%», легко воспроизводится; не вводит выдуманных допущений.
- Как проверим: сравнить тесты с `CASE.md → API-1, REL-1, OBS-1`; привязать к `TRAINING_PR.diff → app/api.py:35-38; app/review_service.py:19-22`; проверить наличие связи с `problem.md → Метрики` и отсутствие логирования содержимого (OBS-1).
