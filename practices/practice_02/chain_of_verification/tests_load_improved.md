# Нагрузочные тесты (улучшенная версия)

## Цели

- Проверить реакции API POST `/api/reviews` при превышении длины `diff` и при таймауте внешнего LLM-вызова.
- Связать результаты с метрикой качества из `problem.md → Метрики`: доля 5xx на POST /api/reviews < 1%.

## Окружение и инструменты

- Генератор HTTP POST к `/api/reviews` (например, k6 или Python `requests`).
- Мок внешнего LLM с управляемой задержкой ответа (для проверки таймаута).
- Журналирование только `request_id`, длительности и статуса без содержимого `diff` и ответов модели (требование `CASE.md → OBS-1`).

## Тест-кейсы

| ID | Назначение | Предусловия | Действие | Ожидаемый результат | Evidence |
|---|---|---|---|---|---|
| L1 | Большое тело запроса | Порог длины `diff` = 20000 символов | Отправить POST `/api/reviews` с `diff` ≈ 22000 символов (на ~10% больше порога) | HTTP 413; отсутствие 5xx; логи без содержимого | `CASE.md → API-1`; `TRAINING_PR.diff → app/api.py:35-38` |
| L3 | Таймаут LLM | Таймаут внешнего LLM = 10 секунд; доступен мок LLM | Смоделировать задержку ответа LLM > 10 секунд | Контролируемый ответ без 5xx; логи без содержимого | `CASE.md → REL-1, OBS-1`; `TRAINING_PR.diff → app/review_service.py:19-22` |

## Критерии провала

- L1: тело > 20000 символов не приводит к HTTP 413; возвращается 5xx; в логах присутствует содержимое `diff` или ответ модели (нарушение `OBS-1`).
- L3: при задержке LLM > 10 секунд возвращается 5xx вместо контролируемого ответа; в логах присутствует содержимое `diff` или ответ модели (нарушение `OBS-1`).

## Связь с метриками

- Оба кейса направлены на снижение доли 5xx на POST /api/reviews до < 1% (см. `problem.md → Метрики`) за счёт корректного 413 и контролируемых ошибок.

## Примечания по верификации

- Порог 20000 символов и требование 413 — `CASE.md → API-1`.
- Таймаут 10 секунд и контролируемая ошибка — `CASE.md → REL-1`.
- Требования к логированию — `CASE.md → OBS-1`.
- Эндпоинт и вызов LLM подтверждены: `TRAINING_PR.diff → app/api.py:35-38; app/review_service.py:19-22`.
