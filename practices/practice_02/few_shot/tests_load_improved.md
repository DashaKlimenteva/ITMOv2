# Нагрузочные тесты (улучшенная версия)

## Цели

- Проверить поведение API POST `/api/reviews` при превышении допустимой длины `diff` и при таймауте внешнего LLM-вызова.
- Связать результаты с метрикой из `problem.md → Метрики`: доля 5xx на POST /api/reviews < 1%.

## Окружение и инструменты

- Генератор HTTP POST запросов к `/api/reviews` (например, k6 или Python `requests`).
- Мок/заглушка LLM с управляемой задержкой ответа для воспроизведения таймаута.
- Наблюдение логов без содержимого `diff` и ответов модели (соблюдение `CASE.md → OBS-1`). Логи должны содержать только `request_id`, длительность и статус.

## Тест-кейсы

| ID | Назначение | Предусловия | Действие | Ожидаемый результат | Evidence |
|---|---|---|---|---|---|
| L1 | Большое тело запроса | Порог длины `diff` = 20000 символов | Отправить POST `/api/reviews` с `diff` длиной ~22000 символов (на 10% больше порога) | Ответ HTTP 413; отсутствие 5xx; отсутствие логирования содержимого | `CASE.md → API-1`; `TRAINING_PR.diff → app/api.py:35-38` |
| L3 | Таймаут LLM | Таймаут внешнего LLM-вызова = 10 секунд; доступен мок LLM | Смоделировать задержку ответа LLM > 10 секунд | Контролируемый ответ без 5xx; логи без содержимого (см. OBS-1) | `CASE.md → REL-1, OBS-1`; `TRAINING_PR.diff → app/review_service.py:19-22` |

## Критерии провала

- L1: тело > 20000 символов не приводит к HTTP 413; возвращается 5xx; в логах появляется содержимое `diff` или ответ модели (нарушение `OBS-1`).
- L3: при задержке LLM > 10 секунд возвращается 5xx вместо контролируемого ответа; в логах появляется содержимое `diff` или ответ модели (нарушение `OBS-1`).

## Обоснование

- Порог 20000 символов и требование 413 подтверждены `CASE.md → API-1`.
- Таймаут 10 секунд и требование контролируемого ответа подтверждены `CASE.md → REL-1`.
- Запрет логирования содержимого подтверждён `CASE.md → OBS-1`.
- Эндпоинт и поток запроса подтверждены `TRAINING_PR.diff → app/api.py:35-38; app/review_service.py:19-22`.
- Кейс параллельности (L2 из `practices/practice_01/tests_load.md`) исключён: «Недостаточно данных» в исходном артефакте и отсутствие порогов/правила в источниках.
- Целевое влияние на метрику качества (`problem.md → Метрики`): уменьшение доли 5xx < 1% за счёт корректных 413 и контролируемых ошибок вместо падений.

## Как использовали AI

- Использовали для систематизации подтверждённых порогов из `CASE.md` и привязки к строкам `TRAINING_PR.diff`; исключали любые кейсы и SLO без источника. Проверка соответствия: `problem.md → Метрики`, `CASE.md → API-1, REL-1, OBS-1`, `TRAINING_PR.diff → app/api.py:35-38; app/review_service.py:19-22`, `practices/practice_01/tests_load.md`.
