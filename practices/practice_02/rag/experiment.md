# RAG

## Вход

- Разрешенные источники:
  - practices/practice_01/CASE.md: правила API-1 (20000 символов), REL-1 (таймаут 10 секунд), QA-1, OBS-1.
  - practices/practice_01/problem.md: метрики, включая «Доля 5xx < 1%».
  - practices/practice_01/TRAINING_PR.diff: app/api.py:35-38; app/review_service.py:19-22.
  - practices/practice_01/tests_load.md: базовые кейсы L1-L3.

## Запрос

Собрать улучшенные нагрузочные тесты на основе API-1, REL-1, QA-1, OBS-1 и метрик из problem.md; задавать только подтвержденные пороги; добавить критерии провала и evidence на кейс; не менять исходный tests_load.md.

## Извлеченный контекст

- API-1: diff длиннее 20000 символов отклоняется с HTTP 413 (CASE.md).
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ (CASE.md).
- QA-1: риск включается, только если подтвержден строкой diff или правилом (CASE.md). Применяем как принцип подтверждения evidence.
- OBS-1: в лог пишутся только request_id, длительность и статус; содержимое diff и ответ модели не логируются (CASE.md).
- Метрика: «Доля 5xx на POST /api/reviews» целевое значение < 1% (problem.md).
- Привязка к диффу: app/api.py:35-38 (эндпоинт POST /api/reviews), app/review_service.py:19-22 (вызов LLM) из TRAINING_PR.diff.
- Базовые кейсы: L1-L3 из practices/practice_01/tests_load.md.

## Результат

- Подготовлен документ с улучшенными нагрузочными тестами, содержащий подтвержденные пороги, инструменты, критерии провала, связь с метриками и evidence на каждый кейс.
