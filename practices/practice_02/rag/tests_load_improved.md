# Нагрузочные тесты (улучшенная версия)

## Источники и пороги

- Порог длины diff: 20000 символов, запросы длиннее отклоняются 413. Источник: CASE.md → API-1.
- Таймаут внешнего LLM-вызова: 10 секунд; ошибка конвертируется в контролируемый ответ. Источник: CASE.md → REL-1.
- Метрика качества: доля 5xx на POST /api/reviews < 1%. Источник: problem.md → «Доля 5xx на POST /api/reviews».
- Базовые сценарии L1–L3 взяты из practices/practice_01/tests_load.md (не изменяя исходный файл).

Примечание: конкретные численные SLO по латентности отсутствуют в источниках; не задаём их «из головы».

## Инструменты и подход

- Генератор параллельных HTTP POST-запросов к `/api/reviews`.
- Мок внешнего LLM с управляемой задержкой ответа для проверки таймаута (есть в L3 исходного сценария).
- Логирование проверяется без записи содержимого diff/ответа модели (только request_id, длительность, статус). Источник: CASE.md → OBS-1.

## Критерии провала

- L1: тело > 20000 символов не приводит к 413; возвращается 5xx; логируются запрещённые данные (нарушение OBS-1).
- L3: при задержке LLM > 10 секунд нет контролируемого ответа; возвращается 5xx; логируются запрещённые данные.

## Связь с метриками

- L1 подтверждает корректное ограничение размера входа и предотвращение 5xx, влияя на метрику «Доля 5xx < 1%».
- L3 подтверждает контролируемую обработку таймаута (без 5xx), что также поддерживает цель «Доля 5xx < 1%».

## Примечания по верификации

- Порог 20 000 и таймаут 10 секунд взяты из CASE.md (API-1, REL-1).
- Числовые SLO по латентности не вводились, так как отсутствуют в извлечённом контексте.
