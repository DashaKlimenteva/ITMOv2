1. Что делали

Я настроила учебную среду для практики: описала правила работы агента в AGENTS.md, добавила skill demo-ci-helper, подняла изолированный MCP-сервер demo-subscribers, подключила hook-плагин и сделала runner на Python вместо make, довела всё до фактических запусков и логов.

2. Что помогло

- AGENTS.md с правилами задал стиль работы: русский язык, TDD, запуск через runner вместо make, запрет сетевых вызовов — агент сразу «ехал по рельсам» и меньше фантазировал.
- Runner на Python вместо make — у меня Windows без make, поэтому питоновский скрипт сразу закрыл этот разрыв и сделал запуск проверок одинаковым.
- Изоляция MCP-сервера в venv — зависимости не загрязняют систему, легко воспроизводить и обновлять.
- Явная загрузка hook-плагина в opencode.json — не полагалась на магию, включила плагин явно и контролируемо.
- Разделение на компоненты: AGENTS.md / skill / MCP / hook / runner — каждый модуль делала отдельно и проверяла по факту; проще отлавливать ошибки и локализовать проблемы.

3. Что мешало

- Windows без make — пришлось писать Python‑runner. Решение: простой run_tests.py, который оркестрирует проверки и сохраняет артефакты.
- OpenCode 1.18.35 — старая версия: событие file.edited в hook не срабатывало. Решение: переключилась на событие завершения инструмента правки (apply_patch); после этого hook начал писать в лог.
- Первый код MCP‑клиента использовал несуществующий API (Client, client.tools.call). Решение: проверила фактический API через dir(mcp) и примеры; перешла на ClientSession + stdio_client.
- Сервер писал отладочный print в stdout — MCP‑клиент падал на «Invalid JSON». Решение: перенаправила отладку в stderr: print(..., file=sys.stderr).
- Плагин не подхватывался без перезапуска OpenCode — это выяснилось только после просмотра hook.log. Решение: перезапустила OpenCode, после чего загрузка плагина подтверждена логом.

4. Где пришлось вмешаться студенту

- Проверка правильности API mcp: dir(mcp), dir(mcp.server) — сверила доступные классы и функции, чтобы не залипать на несуществующих названиях.
- Остановила агента в момент, когда код опирался на несуществующий класс — скорректировала план и код до рабочей версии на ClientSession + stdio_client.
- Согласовала структуру папок и план до старта — чтобы артефакты, skills, mcp и логи разъехались по своим местам.
- Проверила, что practice_03 не тронута — изоляция шагов сохранена.
- Перезапустила OpenCode после добавления плагина — без этого hook не активировался.

5. Что бы сделали иначе в следующий раз

- Сразу проверять фактический API библиотек (dir, help), а не доверять памяти модели.
- Сразу использовать актуальную версию OpenCode (2.0.x), под которую писалась презентация практики.
- Регулярно смотреть hook.log, а не надеяться, что «hook должен работать».

6. Итог

- Среда настроена: AGENTS.md, skill demo-ci-helper, MCP‑сервер demo-subscribers, hook‑плагин, runner на Python.
- Skill и MCP подтверждены фактическими запусками: artifacts/run_*.md и artifacts/mcp_test_run.txt.
