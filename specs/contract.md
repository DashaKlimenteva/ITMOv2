# Contract: CLI Lab Report Generator (UI ↔ Logic)

## Данные (входные параметры)

- lab: тип int (целое ≥ 1). Обязателен, если не указан `--out`. Значение по умолчанию отсутствует; при отсутствии и без `--out` — ошибка аргументов.
- fio: тип string. Необязателен. По умолчанию отсутствует; плейсхолдер `{FIO}` остаётся без изменений.
- group: тип string. Необязателен. По умолчанию отсутствует; плейсхолдер `{GROUP}` остаётся без изменений.
- date: тип string в формате ISO `YYYY-MM-DD`. Необязателен. По умолчанию — текущая системная дата в ISO; подставляется в `{DATE}`. При переданном неверном формате — ошибка аргументов.
- out: тип path (путь к файлу). Необязателен. По умолчанию — вычисляется из `lab` как `reports/labNN.md` (NN — с лидирующим нулём для 1–9, иначе без нуля). Если `--out` задан, используется он, `lab` влияет только на подстановку `{LAB}`.

Правила подстановки:
- Если аргумент не передан, соответствующий плейсхолдер остаётся как есть, кроме `date` — для него по умолчанию подставляется текущая дата ISO.

## Вызовы: команда и флаги

- Команда: `python tools/new_lab_report.py`
- Синтаксис:
  - `python tools/new_lab_report.py --lab <int> [--fio <string>] [--group <string>] [--date <YYYY-MM-DD>] [--out <path>]`
  - Если `--out` не указан, `--lab` обязателен (для вычисления имени файла по умолчанию).
- Флаги и типы:
  - `--lab <int>=1..`: номер лабораторной.
  - `--fio <string>`: ФИО.
  - `--group <string>`: группа.
  - `--date <YYYY-MM-DD>`: дата в ISO.
  - `--out <path>`: путь к выходному файлу.

## Коды возврата и соответствие ошибкам

- 0: успех, файл создан, запись завершена в UTF-8.
- 1: ошибки файла/шаблона/IO и прочие runtime-ошибки после парсинга.
  - Шаблон недоступен/не найден (`templates/lab_report.md`).
  - Выходной файл уже существует (не перезаписывать).
  - Ошибки создания директорий/записи файла.
- 2: ошибки аргументов (парсинг/валидация).
  - Отсутствует обязательный `--lab` при отсутствии `--out`.
  - `--lab` не число или `< 1`.
  - `--date` не в формате `YYYY-MM-DD`.

## Состояния

- success: код 0; файл создан; путь разрешён (абсолютный/относительный — по входу) и доступен.
- error: общее состояние неуспеха; см. разбиение по кодам 1/2.
- file_exists: частный случай ошибки файла; код 1; файл не перезаписывается.
- missing_template: частный случай ошибки шаблона; код 1; файл не создаётся.

## Ожидания UI ↔ Logic

Что UI ожидает от логики:
- Возврат кода завершения согласно таблице выше (0/1/2) без пользовательских текстов.
- Отсутствие побочных эффектов при неуспехе: никакого создания/изменения файлов при коде ≠ 0.
- При успехе — созданный файл по вычисленному пути. Логика возвращает путь (в программном API) либо позволяет его детерминированно вычислить по тем же правилам.

Что логика ожидает от UI:
- Передачу флагов и значений в точности по контракту типов.
- Не полагаться на вывод логики для пользовательских сообщений; UI сам формирует сообщения на основе кода возврата и контекста вызова.
- При успехе UI выводит абсолютный путь к созданному файлу в stdout; при ошибках — сообщения в stderr, при этом UI не изменяет код возврата, пробрасывая его наружу.

## Поведение путей и файлов

- Шаблон: `templates/lab_report.md` с плейсхолдерами `{LAB}`, `{FIO}`, `{GROUP}`, `{DATE}`.
- Разрешение выхода:
  - Если задан `--out`, используется он (создать недостающие родительские директории).
  - Иначе по умолчанию: `reports/labNN.md` (NN — zero-pad для 1–9, иначе число без нуля). Требует валидного `--lab`.
- Если целевой файл существует — завершить с кодом 1, файл не изменять.

## Расхождения и принятые решения

1. Место создания файла по умолчанию:
   - UI-спека: «по умолчанию создаётся в текущей директории с понятным именем».
   - Логика-спека: `reports/labNN.md`.
   - Решение: источник истины — логика. Принято `reports/labNN.md`. UI будет отражать это поведение в сообщениях и тестах.

2. Коды возврата при ошибках аргументов:
   - UI-спека: упоминает «ненулевой код (например, 1)» без детализации.
   - Логика-спека: 2 — ошибки парсинга/валидации аргументов; 1 — ошибки файла/шаблона.
   - Решение: принять схему логики (2 — аргументы, 1 — файл/шаблон). UI не должен нормализовать код к 1, а пробрасывает код логики.

3. Сообщение об успешном пути:
   - UI-спека: печатать абсолютный путь в stdout.
   - Логика-спека: тексты вне scope.
   - Решение: печать — ответственность UI. Логика предоставляет детерминированное вычисление пути; при интеграции библиотечного вызова — возвращает путь как значение (без печати).

4. Значение по умолчанию для `date`:
   - Обе спеки согласны на ISO `YYYY-MM-DD`. Логика уточняет: если не передан, использовать системную дату. Для других полей — оставлять плейсхолдеры.
   - Решение: принять особое правило для `date`: по умолчанию подставлять текущую дату.

5. Приведение кодов и валидации (implement):
   - `--lab < 1` → код 2 (ошибка аргументов), не 1. Текущая реализация `python tools/new_lab_report.py` возвращает 1 — на шаге implement приведём к контракту.
   - `--date` не в формате `YYYY-MM-DD` → код 2; валидация добавляется на шаге implement.

## Примеры вызовов

- Явный путь:
  - `python tools/new_lab_report.py --lab 10 --fio "Иванов И.И." --group K3141 --date 2026-10-29 --out docs/labs/lab10.md`
  - Ожидание: код 0, создан `docs/labs/lab10.md`.

- Путь по умолчанию (из `lab`):
  - `python tools/new_lab_report.py --lab 7 --fio "Иванов И.И." --group K3123`
  - Ожидание: код 0, создан `reports/lab07.md`, `{DATE}` = текущая ISO дата.

- Ошибка аргументов:
  - `python tools/new_lab_report.py --lab 0` → код 2, файл не создан.
  - `python tools/new_lab_report.py --date 2026/10/29 --out a.md` → код 2, файл не создан.

- Ошибки файла/шаблона:
  - Целевой файл существует: код 1.
  - Отсутствует `templates/lab_report.md`: код 1.

## Совместимость и инварианты

- При любом неуспехе (код ≠ 0) логика не должна оставлять частичных/неполных файлов.
- UI выводит сообщения, но не меняет код возврата, полученный от логики.
